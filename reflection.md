# Portfolio Reflection

The main decision I made was how to present two identities at once: a security architect industry experience, and a graduate student building new depth in computer science and AI. I organized the profile README so visitors see both right away. A short headline and two-sentence summary come first, then a "Start here" table that tells them where to go: pinned repositories for hands-on code, project READMEs for performance analysis, and my résumé for career history. I pinned only finished, documented projects instead of filling the profile with placeholders.

The portfolio and résumé are designed to complement each other. My résumé summarizes two decades of work in cryptography, PKI, and cloud security, which mostly lives in private enterprise systems I can't publish. My GitHub portfolio fills that gap with visible evidence: C programs using threads, sockets, and memory-mapped files, along with benchmarks and plots that show how I reason about performance. The "Focused on now" and "Goals" sections connect these together and explain my direction: applying AI to security and preparing for post-quantum cryptography.

The part I most want to develop is a portfolio that combines my professional expertise with what I learn in the program. Right now, my public code comes from systems coursework. As I take AI and machine learning courses, I plan to build and publish a self-directed project that applies machine learning to a real security problem, such as detecting anomalies in certificate or key usage, with a clear write-up of the design and results.
